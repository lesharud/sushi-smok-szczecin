# Sushi Smok — restaurant web-app

**Текущая публикация через GitHub + Vercel:** пошаговая инструкция в [DEPLOY-VERCEL.md](DEPLOY-VERCEL.md). Конфигурация `vercel.json` подготовлена; обязательных переменных для demo нет. Ранее подготовленный вариант Netlify описан ниже как альтернативный.

Существующий премиальный сайт расширен без пересоздания проекта. React 19, Vite, TypeScript, React Router 7, CSS, Lucide. Локальные шрифты DM Sans / Cormorant Garamond и WebP. Весь интерфейс на польском. Основная айдентика, главный экран, история, галерея и контакты сохранены.

## Запуск

Требуется Node.js 22.12+.

```sh
npm ci
npm run dev
```

Обычно http://localhost:5173; если порт занят, Vite выводит следующий свободный адрес. Сервер доступен в локальной сети. Сборка: `npm run build`; просмотр production: `npm run preview`.

## Страницы и сценарии

- `/` — главная с интерактивными блюдами и дополнительной подборкой наборов.
- `/menu` — каталог, поиск по названиям/описаниям, закреплённые категории.
- `/menu/kategoria/:category` — одна из 16 реальных категорий.
- `/menu/danie/:slug` — фото, состав из источника, количество, цена, добавление в корзину.
- `/cart` — корзина; также доступна через drawer/sheet в навигации.
- `/checkout` — контакты, самовывоз/доставка, адрес, предпочтительное время и способ оплаты, валидация на польском.
- `/order-success/:id` — локальный тестовый чек с номером `TEST-*`.
- `/account`, `/account/orders` — профиль, редактируемые адреса и история на текущем устройстве.
- `/login`, `/register` — Supabase Auth после настройки ключей; без них честное сообщение о недоступности аккаунтов.

Корзина хранит productId/quantity в localStorage, пересчитывает сумму в грошах, синхронизируется между вкладками. Изменение количества, удаление и пустые состояния работают. Мобильная нижняя навигация, safe-area, закреплённые CTA, toast и keyboard-accessible native dialog добавлены без тяжёлой библиотеки анимации.

**Заказ тестовый.** Ресторан не получает отправку, платежи не списываются. Сохранён реальный переход в Wolt. Тариф доставки неизвестен и не подменён нулём. Полный чек временно хранится в sessionStorage; история обезличена, если клиент не выбрал сохранение данных. Кнопки удаления доступны в профиле.

## Данные и backend

68 позиций из публичного меню Sushi Smok на Wolt, проверка 14.09.2026. 48 позиций имеют собственные фотографии ресторана; у остальных фирменное состояние «Zdjęcie wkrótce». Цены и количество штук взяты из источника; граммовки и аллергены без подтверждения оставлены null.

- `src/shop/catalog.json` — единый редактируемый каталог: цена в грошах, описание, категория, фото, available, provenance.
- `src/shop/types.ts`, `catalog.ts` — модели и функции доступа.
- `src/shop/ShopProvider.tsx` — корзина и toast.
- `src/shop/orders.ts` — demo-реализация интерфейса OrderRepository.
- `src/shop/auth.tsx` — ленивый Supabase SDK, настоящие sign-up/sign-in/sign-out при наличии ключей.
- `supabase/migrations/`, `supabase/seed.sql` — схема БД с RLS и снимок каталога.
- `.env.example`, `BACKEND.md` — настройка и контракт подключения сервера.

Ключи Supabase не предоставлены; реальная авторизация и SQL на удалённом проекте не тестировались. Локальные профиль/история не являются защищённым облачным аккаунтом. Подробности и следующие шаги production — в `BACKEND.md`.

## Где редактировать интерфейс

`src/App.tsx` — сохранённая главная; `src/Root.tsx` — маршруты; `src/pages/` — новые страницы; `src/shop/Shell.tsx` — общая навигация и корзина; `src/shop/components.tsx` — карточки и контролы; `src/styles.css` — исходная дизайн-система; `src/shop.css` — её расширение. `src/data.ts` хранит проверенные контакты и редакционные подборки главной. Стоимость карточек главной берётся из каталога.

`public/images/menu/` — дополнительные оригиналы и WebP. Оптимизация: `node scripts/optimize-menu.mjs`. Импорт из сохранённого Wolt assortment: `python3 scripts/import-menu.py path/to/assortment.json` — вручную, чтобы не перезаписать правки владельца. Seed: `node scripts/seed-catalog.mjs`.

## Публикация и SEO

```sh
SITE_URL=https://your-domain.pl VITE_SITE_INDEXABLE=true npm run build
```

Заменить домен на настоящий, включать индексацию только после согласования запуска. По умолчанию `VITE_SITE_INDEXABLE=false`: preview закрыт от индексации через robots и meta. Переменные можно задать в `.env.local` по `.env.example` или в панели хостинга. После изменения нужна новая сборка. Публиковать только `dist/`. Главная, категории и блюда предварительно рендерятся в HTML; создаются canonical, OG и sitemap. Сервисные страницы noindex.

Рекомендуемый frontend-хостинг — Netlify: настройки сборки находятся в `netlify.toml`, маршруты в `public/_redirects`, заголовки кеша в `public/_headers`. Существующие HTML-страницы обслуживаются напрямую, `/order-success/*` получает оболочку приложения, неизвестные адреса — страницу 404 с HTTP 404. Проверить эти статусы на согласованном staging: Vite preview использует собственный fallback. Подключить домен владельца через DNS и включить автоматический SSL. Деплой в этом проходе не выполнялся.

Для серверной части подходит Supabase Postgres + Edge Functions; подключение описано в `BACKEND.md`. Одни `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` включают только авторизацию, не приём заказов. Service-role ключи и платёжные секреты хранятся только на сервере, никогда в `VITE_*`. Manifest и иконки готовы; service worker не добавлен, чтобы offline-кеш не вводил в заблуждение при заказе.

## Изменение меню и контактов

- Цена: в `src/shop/catalog.json` изменить `priceGrosz`, например 3900 означает 39 zł. Затем пересобрать проект.
- Блюдо: изменить `name`, `description`, `pieces`, `weightGrams`, `available` у нужной записи согласно типам в `src/shop/types.ts`. Не менять `id` без миграции сохранённых корзин; изменение `slug` требует редиректа со старого адреса.
- Изображение: положить разрешённый владельцем файл в `public/images/`, обновить путь `image` на `/images/имя.webp`. Не указывать локальный путь компьютера. Проверить crop на мобильном и desktop.
- Контакты и часы: `src/data.ts`; синхронизировать данные Restaurant JSON-LD в `scripts/prerender.mjs`. Условия доставки/режим заказа: `src/shop/catalog.ts`. Не включать реальные заказы простым изменением demo-флага.
- Истории Section 03: `src/home/EditorialGallery.tsx`; фото — `gallery` в `src/data.ts`. Геометрия мобильной оболочки и safe areas — `src/prelaunch.css`.

## Передача клиенту

Передать исходники и lockfile, доступы к репозиторию, хостингу, домену и backend на аккаунтах владельца. Секреты передавать отдельно. Получить подтверждение данных из `PRELAUNCH.md`, прав на фото и логотип, условий доставки и оплаты, контактных и юридических текстов. Настроить получение заказов рестораном, мониторинг ошибок, резервные копии БД и порядок обновления меню. Провести контрольный реальный заказ на staging и проверку физических iPhone/Android. До этого сайт пригоден для демонстрации, но собственный production-приём заказов не готов.

## Проверки

```sh
npm run build
npm run test:e2e
```

Playwright использует установленный Chrome на macOS; на другой системе указать `PLAYWRIGHT_CHROME_PATH`. Тесты покрывают старую главную, меню, маршруты, поиск, корзину, сохранение, checkout, тестовый чек, профиль/адреса, ширины 320–1920 px и axe WCAG AA. Скриншоты: `test-results/`. Мобильные проверки выполняются в браузерной эмуляции; физический iPhone/Safari пока не проверен.

Источники, ограничения и права: `SOURCES.md`. Instagram-айдентика и дизайн-исследование: `DESIGN.md`. Перед настоящим запуском владелец должен подтвердить цены прямого заказа, составы/аллергены, фото, график, доставку и оплату; затем подключить сервер заказов, канал ресторана и платежи при необходимости.
